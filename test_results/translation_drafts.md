## Verdict: not correctable

Read against the one question this was run to answer — *would fixing this be
faster than writing it from scratch?* — the answer is no, by a wide margin.

**Objective evidence, independent of anyone's Urdu:**

| | |
| --- | ---: |
| placeholders surviving the hop | **0 / 43** |
| drafts containing hallucinated format specifiers (`%s`, `%d`) | **9 / 50** |

The format specifiers give the cause away. `opus-mt-en-ur` was trained largely
on software localisation strings, so given text that looks like it belongs in a
program it emits `%s`, `%d`, `%d-%d ,%s'%s` — artefacts of gettext catalogues,
not translations of anything.

**And the meanings do not survive**, which matters more:

| English | Urdu, back-translated |
| --- | --- |
| "To merge two sorted arrays into one sorted array" | "to divide into two different pieces" — the opposite operation |
| "An integer representing the minimum number of deletions required" | "what was the reason for this?" — unrelated, and a question |
| "Computes the determinant using the formula ad - bc" | "write this process in order" — unrelated |

A draft that says the opposite of the source is worse than a blank line,
because it has to be read carefully before it can be rejected.

## What this rules out, and what it does not

**Ruled out:** `opus-mt-en-ur` as the generator. Not tunable, not correctable,
wrong training domain.

**Not ruled out:** the two-hop idea itself. This tested the cheapest possible
first hop, and it failed on register exactly as `LANGUAGE_RESEARCH.md` predicted
a news-and-localisation corpus would — the prediction was that technical nouns
would come back as formal Urdu, and the reality is worse.

Worth testing next, in this order:

1. **A frontier LLM as the teacher.** ERUPD itself was built with "synthetic
   data generated via advanced prompt engineering", which is this. A large model
   can produce Roman Urdu directly in a developer register, skipping the Urdu
   hop entirely, and distilling a teacher into a small model is standard.
2. **NLLB-200-distilled-600M.** A real multilingual system with genuine
   `urd_Arab` training data rather than localisation strings. 2.5 GB, so worth
   running where the connection is fast.

**Not worth doing:** correcting these. Fifty drafts took under a minute to
generate and would take longer to repair than to write.
